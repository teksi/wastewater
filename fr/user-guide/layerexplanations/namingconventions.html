Conventions de nommage

Schémas de la base de données TWW

Le schéma des bases de données TEKSI suit toutes les mêmes règles. Pour les distinguer, chaque infrastructure possède son propre préfixe (3 lettres). TWW (TEKSI wastewater) est le préfixe du module de gestion du réseau d’assainissement. La base de données TWW comporte quatre schémas tww :

  • tww_od : dans ce schéma se trouvent les tables stockées de manière persistante. Elles correspondent principalement au modèle de données VSA-DSS (cover, wastewater_node, channel, etc.), mais incluent aussi certaines couches nécessaires à la symbologie et à l’étiquetage, ainsi que les séquences de ces tables. En raison de la nouvelle gestion des mises à jour, les vues ne se trouvent plus dans le schéma *_od, mais dans le schéma *_app.

  • tww_vl : c’est le schéma des listes de valeurs. Il existe une table pour chaque liste de valeurs du VSA-DSS. En tant qu’utilisateur TWW, vous ne pouvez pas modifier ces tables.

  • tww_app : schéma pour toutes les vues, vues matérialisées, fonctions, triggers, etc. spécifiques au module, ainsi que pour les vues et fonctions des extensions complémentaires (SWMM, QField). En cas de mise à jour de la base de données, ce schéma sera écrasé.

  • tww_sys : tables spéciales pour l’administration de la base de données. En tant qu’utilisateur TWW, vous ne pouvez pas modifier ces tables.

Si l’import ou l’export INTERLIS est utilisé, des schémas supplémentaires tels que « tww_app_pg2ili » seront créés. Ils sont recréés à chaque import ou export. N’ajoutez pas ces schémas au projet TWW.

Noms de couches

  • Noms de couches sans préfixe

Cela indique que vous trouverez la table dans le schéma tww_od (ou, si elle se trouve dans le groupe de couches « Value Lists », dans le schéma tww_vl). Si vous n’êtes pas sûr du schéma dans lequel chercher la table : placez la souris sur la couche et regardez dans l’infobulle jaune la mention “table= »tww_*”.

  • Noms de couches commençant par vw_

Deux tables VSA-DSS ou plus sont jointes dans une vue (vw). La couche porte le nom de la table principale. Exemple : vw_tww_reach : la couche principale est la table reach (et non la table channel). Il est important de connaître la table principale pour être sûr d’utiliser les bons attributs.

Noms d’attributs

  • Préfixes dans les noms d’attributs

Dans une vue, vous trouvez des champs provenant de différentes tables. Dans les cas simples, seules une sous-classe et une superclasse sont incluses. Dans les couches principales de TWW, plusieurs sous-classes et superclasses sont présentes. Le préfixe du nom d’attribut indique à quelle table appartient l’attribut. Le préfixe est constitué de deux lettres correspondant à une table du modèle de données VSA-DSS. Exemple : co = cover, ws = wastewater structure. La convention est la suivante : les attributs de la table principale n’ont pas de préfixe, tous les autres attributs ont un préfixe indiquant la table dont ils proviennent. Dans le cas d’une sous-classe et d’une superclasse, les deux tables sont considérées ensemble. Exemple dans la couche vw_tww_reach : identifier est un attribut de la table wastewater_networkelement (la superclasse de la table principale reach) et n’a donc pas de préfixe. Material se trouve dans la table reach, sans préfixe car c’est la table principale. ch_usage_current est un attribut de la table channel. ws_remark est l’attribut remark de la table wastewater_structure.

  • Champs fk_

fk_ n’est pas le préfixe d’une table particulière. Il signifie « foreign key » (clé étrangère).

  • Champs commençant par _

Les attributs commençant par _ (tiret bas) sont des champs calculés. Vous ne les trouverez pas dans les schémas. Exemples : _slope_per_mill dans vw_tww_reach. _channel_usage_current dans vw_tww_wastewater_structure est calculé à partir du champ usage_current du channel, connecté via la clé étrangère du wastewater_networkelement en tant qu’exutoire (outlet) vers un regard ou un ouvrage spécial.
